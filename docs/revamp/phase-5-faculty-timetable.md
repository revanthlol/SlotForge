# Phase 5 — Faculty Timetable + Shareable Links

**Agent:** Codex  
**Depends on:** Phase 1 (faculty timetable endpoint), Phase 2 (frontend structure)  
**Blocks:** Nothing  
**Estimated effort:** Small-Medium (1–2 days)

---

## Goal

Give admins a **per-faculty timetable view** and the ability to generate a
**public shareable link** for each faculty member's timetable. No faculty login
is required — the shareable link is the access mechanism.

This was inspired by how real college timetabling works: the central office
builds the timetables and distributes them to faculty. SlotForge automates
this distribution via shareable links.

---

## Feature Spec

### Shareable Link Generation

Admin clicks "Share" button on a faculty timetable → generates a public link:

```
https://slotforge.vercel.app/share/faculty/{share_token}
```

The `share_token` is a **random UUID** stored in the DB:
```python
class FacultyShareLink(Base):
    id: UUID
    token: str            # random UUID, used in the URL
    resource_id: UUID     # which faculty
    schedule_run_id: UUID # which version of the timetable
    created_by: UUID      # admin user
    expires_at: datetime | None  # optional expiry
    is_active: bool
```

The share page (`/share/faculty/{token}`) is **fully public** — no login, no auth.
It shows a read-only version of the faculty timetable.

## Backend Endpoints Needed (Antigravity — already started in Phase 1)

```
GET  /api/v1/workspaces/{id}/resources/?type=teacher
     → list all teachers/faculty

GET  /api/v1/workspaces/{id}/schedule-runs/{run_id}/faculty/{resource_id}/timetable
     → returns timetable grid for that faculty member

POST /api/v1/workspaces/{id}/faculty/{resource_id}/share-link
     body: { schedule_run_id, expires_at? }
     → returns { token, share_url }

GET  /api/v1/share/faculty/{token}
     → public endpoint, no auth, returns timetable + faculty info

DELETE /api/v1/workspaces/{id}/faculty/{resource_id}/share-link/{link_id}
     → deactivates / revokes the share link
```
